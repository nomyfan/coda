## Problem

让工具输出的采集内存、磁盘保留和模型可见内容分别有界，同时让 agent 与用户能回查仍被保留的全文。需求见 [tool-output-limits.md](../requirement/tool-output-limits.md)。

## Scope

- 覆盖前台 `shell` / `grep` / `glob` / `ls`、`read_file`、后台 shell 和子 agent 结果、普通及 MCP 工具文本、PTC 内部资源及最终输出。
- 包含配置、结果存储、通过现有文件工具回查、消息持久化、会话生命周期和最小 UI 提示；不增加专用结果搜索工具或独立日志浏览器。
- 不限制第三方 MCP 实现内部内存，不重做上下文压缩，不把模型输入图片、文件 diff artifact 或全部历史的存储纳入文本结果磁盘配额。
- PTC 中间结果不进入模型展示和历史归档流程；必要的临时落盘仍受资源配额约束，最终值、显式日志及错误才构成 PTC 对外结果。

## Assumptions

- 服务仍为 Unix 部署；一个输出根目录由一个服务进程独占锁定。服务级配额覆盖该根目录全部工作区及会话，不是多机器共享配额。
- 用户已确认：磁盘配额耗尽或写盘失败时，命令继续执行；停止保存后续全文，继续排空管道，保留有限首尾预览并明确标记不完整。
- 正在运行的后台作用域仍禁止 fork / rewind / 手动 compact / SetModel，沿用当前检查；不新增运行中复制日志的语义。
- 全文可回查受期限、配额及实际采集完整性约束。`read_file` 的原文件可以由用户修改，不承诺将未读取内容保存成历史快照。
- 用户选择以落盘文件的绝对路径作为 LLM 回查入口，复用 `read_file` / `grep` / `shell`。当前工具在服务端本机执行，workspace 是默认目录而非文件系统 sandbox；输出目录必须处在工具进程可读的本机文件系统。
- 不额外授予 agent 文件工具；未配置读取/搜索工具的 agent 可将路径交给有相应工具的调用方，不能据此绕过工具配置或审批。

## Validation Findings

以下均通过现有源码核对，未修改实现或运行压力测试：

| 问题 | 证据 | 设计影响 |
| --- | --- | --- |
| 前台采集是否已经有界 | `coda_tools/src/process.rs::run_command` 对两路管道使用 `read_to_end(Vec)` | 必须在读取阶段改变存储方式，不能只在返回后截断 |
| 后台文件能否直接充当全文存储 | `DiskTail` 会覆盖头部；`SessionQuota` 固定为 64 MiB；没有服务级总配额 | 替换字节存储，保留任务执行、通知和取消机制 |
| 读完是否有副作用 | `BackgroundTasks::read` 返回前持久化游标；`ToolCallContext::record_task_result` 关联已读确认 | 先分配输出预算，按实际交付范围提交游标和确认 |
| `read_file` 是否按需读盘 | `fs.rs` 先 `read_capped` 整个文件，再按行截取 | 改成流式定位及限量读取，保留写文件工具的独立大小限制 |
| PTC 数据是否可直接预览化 | `HostToolCallResult.output` 是原始字符串；`engine.rs` 在结果通过大小检查后提交 staged effects | 原始数据通路与模型展示通路分开，超限不能伪装为成功的截断数据 |
| PTC 累计结果大小是否代表内存占用 | `engine.rs` 对已交付结果累计字节数，处理完的数据也不会从累计值扣除；JS heap 限制不覆盖 Rust 缓冲 | 删除单次/累计中间结果大小限制，改管实际驻留的原生缓冲、在途数据和 JS heap |
| 同步日志能否等待结果释放内存 | `bootstrap.js` 的 console.log 同步调用原生 appendLog；`engine.rs` 在 JS worker 的单线程 runtime 中等待并转换 host 返回值 | 日志必须使用不可被待交付结果占用的预留空间，并在 JS worker 之外排空，否则两者可能循环等待 |
| 结果引用能否随消息保存 | `ToolMessage` 已保存在消息 JSON；fork 复制 payload，rewind 删除消息行 | 引用加入消息 payload，正文不进入数据库；无需给每份结果另建数据库聚合 |

## Alternatives Considered

| 决策 | 备选 | 选择及代价 |
| --- | --- | --- |
| 全文保留 | 只保留内存首尾；或后台环形文件 | 采用可封存的顺序文件，满足中间内容回查；接受磁盘管理成本 |
| 回查入口 | 原方案按结果 ID 新增只读工具、字面量搜索和 RPC | 改为返回绝对文件路径，复用现有工具；原方案重复实现读取/搜索，已按用户反馈放弃。接受回查依赖已有工具权限，文件删除后按普通文件缺失反馈 |
| 存储归属 | 把所有结果伪装成后台 task | 提取独立 `coda_output`，不制造任务 ID、完成通知和后台 capability；后台执行层也使用同一存储 |
| fork | 原方案复制文件；或共享引用计数控制删除 | 改为稳定路径与独立保留期限，fork 直接保留路径，不复制或续期。接受删会话不立即删全文、继承结果仍可能被期限/配额淘汰，避免改写历史文本中的路径及引入引用计数 |
| 同批预算 | 结果完成时抢占余额；全部完成后重新分配 | 执行前等分预算，便于分页读取、审批恢复和结果即时持久化；接受小结果没用完的额度不再分配 |
| 计量单位 | tokenizer 精确计量；按固定比例估算 tokens | 使用 UTF-8 字节预算，跨 provider 一致且有严格上限；不声称字节预算等于 token 数或保证整段上下文不溢出 |
| 封存失败 | 原方案要求先封存成功，但未定义失败出口；或将工具改判失败 | 返回原执行状态及有界预览，单独报告存储不可用，不发布未封存引用；接受无法回查这部分全文 |
| 取消后的输出整理 | 原方案主动取消时不再等待磁盘操作 | 立即停止执行，在独立且有界的整理期限内保存已有输出；取消本身不代表存储失败，接受短暂收尾等待 |
| PTC 中间数据 | 按单次/累计字节拒绝结果，并自动归档中间结果、生成诊断索引 | 改为 PTC 管理实际资源，中间数据保持原文；仅最终回复进入统一展示和保留流程。接受中间结果不自动保留供历史回查，避免累计处理量限制分批计算，以及维护并非模型所需的索引 |
| PTC 日志内存 | 日志与待交付结果按需竞争全部额度 | 从同一总预算中预留日志空间，外部 IO 排空后归还日志队列槽位；接受结果可用内存略减，保证同步日志不依赖 JS worker 消费结果才能推进 |

## Components

- **`coda_core::output`**：定义结果 ID、数据来源、完整性、读取凭证及存储 trait；不负责文件系统或配额实现。
- **新 crate `coda_output`**：依赖 `coda_core`，拥有采集器、文件存储、全局及会话配额、恢复与清理；只为后台读取和 PTC 物化提供内部范围读，不实现文本搜索或新的 LLM 工具。现有 fd-relative 路径安全实现迁入并去除 TaskId 耦合，禁止再建一套功能相同的目录安全代码。
- **`coda_execution`**：继续拥有进程组、后台 task 生命周期及通知；日志和最终答案改为持有输出引用，原环形存储及独立 payload 配额退出新路径。
- **`coda_agent`**：为每批模型发起的调用分配展示预算；将直接返回模型的工具及子 agent 结果变成有界消息，PTC 内部调用绕过该展示入口；将读取凭证纳入 checkpoint 事务，接入历史请求的预算兜底。
- **`coda_tools` / `coda_ptc`**：分别实现有界命令/文件读取和 PTC 的 heap、原生缓冲、在途数据管理；PTC 日志及最终报告接入统一输出流程，执行器仍拥有各自取消与超时语义。
- **`coda_server` / `coda_web`**：服务端加载配置并独占输出根目录，连接存储与会话生命周期；网页显示可复制的服务端文件路径和完整性/期限提示，已有后台结果区保留有界翻页，不另建通用结果查询 API。

## Configuration

配置均在 `coda-server.toml`；以下为本方案建议的首版默认值，单位为字节或秒，重启生效。

| 配置 | 默认值 | 合法范围 / 含义 |
| --- | --- | --- |
| `[resources.output].root` | `<系统临时目录>/coda-output` | 绝对路径，或相对配置文件目录解析；生产部署可设持久目录 |
| `capture_memory_bytes` | 262144（256 KiB） | 64 KiB–4 MiB；每个调用 stdout/stderr 合计的采集缓存预算 |
| `result_max_bytes` | 67108864（64 MiB） | 1 MiB–1 GiB；一份结果所有内容通道的文件总量 |
| `session_disk_bytes` | 536870912（512 MiB） | ≥ `result_max_bytes`，≤ 1 TiB |
| `total_disk_bytes` | 4294967296（4 GiB） | ≥ `session_disk_bytes`，≤ 16 TiB；全服务合计 |
| `retention_secs` | 86400（24 小时） | 60–2592000（30 天）；从封存时间计算，读取不续期 |
| `[resources.output.model].single_bytes` | 16384（16 KiB） | 1–256 KiB；每次工具响应正文，包括状态、分页游标、引用及提示 |
| `batch_bytes` | 65536（64 KiB） | ≥ `single_bytes`，≤ 1 MiB；同一 assistant message 发起的一批工具响应正文合计 |
| `[resources.ptc].timeout_secs` | 120 | 1–600；包括等待 worker / host 调用的时间 |
| `heap_bytes` | 67108864（64 MiB） | 8 MiB–512 MiB；JS heap，不是进程总内存 |
| `max_calls` / `max_concurrent_calls` | 128 / 16 | 1–1024 / 1–64；并发数不得大于调用次数 |
| `host_buffer_bytes` | 67108864（64 MiB） | 4 MiB–512 MiB；每次 PTC 执行持有的原生结果缓冲、采集队列及转换临时数据合计，不累计已释放数据 |
| `final_bytes` | 1048576（1 MiB） | 1 KiB–16 MiB；最终 JSON 报告不含日志的序列化资源上限，非模型展示预算 |

- 模型项可用 `output_limits = { single_bytes = ..., batch_bytes = ... }` 逐字段覆盖 `[resources.output.model]`；子 agent 显式模型覆盖使用自己的模型预算，返回父 agent 时使用父调用已分配的预算。
- 配置在加载时一次性验证范围及相互关系，错误包含完整字段路径；`0` 不表示无限。`ptc.final_bytes` 不得超过单份磁盘上限；值解析和算术均检查溢出。不再提供 `result_bytes` / `total_result_bytes`，PTC 已处理并释放的数据不消耗后续调用的内存额度。
- 全局展示预算和每个模型覆盖值都使用最终解析后的 output root 校验。首版共用 `ModelOutputLimits::minimum_response_bytes`：按四个通道、最大计数及时间字段生成完整的已保存文件说明文本，另预留 512 字节给执行状态、截断原因及续读信息。这是无正文预览时的保守下限；后续展示和批次派发复用同一计算，并将引用以外的必要元数据约束在该预留内。
- `host_buffer_bytes` 包含不可借用的日志预留量：`capture_memory_bytes + 64 KiB`（默认 320 KiB），用于日志采集/首尾预览及固定分块、排队和在途 IO。剩余额度供 host 结果等非日志缓冲使用；加载时验证剩余至少 64 KiB。该分配为内部规则，不新增配置项，也不额外增加总内存上限。
- 内部保留 PTC source 256 KiB、stack 512 KiB、join grace 1 秒、4 个 worker、state 4 MiB 和 artifact 32 MiB 的限制。原 `stdout_bytes` 不再是丢弃日志的独立阈值，日志复用 output 的采集/存储/展示预算。
- 额外保留不可配置的边界：每份结果最多 4 个命名通道、每会话最多 4096 份输出对象、全服务最多 65536 份，单个 manifest 最多 8 KiB；数量限制防止大量空文件绕过字节配额。普通并发调用总内存仍随并发数增长，本方案不引入全服务任务调度器。
- PTC 中间采集使用相同的单份、会话及服务磁盘配额；临时文件只保留到交付或放弃，清理完成后释放额度，不进入最终结果的保留期限或历史引用。后台任务自己的日志继续按任务规则保留，不因 PTC 读取而额外归档一份。
- `[background].root` 继续保存 task 执行与通知元数据；新日志 payload 统一归 output root 管理。资源预算不是 workspace 授权，agent 不能通过参数提高服务端上限。

## Interfaces

以下为跨模块接口草图，省略常规错误转换及 trait 的 Future 装箱写法；类型落在 core，实现落在 output。

```rust
enum CapturePurpose {
    Foreground,
    Background,
    Programmatic(BufferBudget),
}

// 返回有界采集句柄；用途决定最终保留还是仅供程序消费的临时缓冲。
// Programmatic 的内存预留同时受 PTC 的 BufferBudget 约束。
fn begin(&self, owner: SessionKey, channels: &[Channel],
         purpose: CapturePurpose) -> OutputCapture;

// 接受一块数据；存储失败写入完整性状态，不把已经执行的命令改判失败。
// 执行取消时已有数据移交有界收尾；写入受 IO/整理截止时间约束，取消本身不是存储故障。
async fn append(&mut self, channel: Channel, bytes: &[u8]) -> CaptureStatus;

// Foreground 在 deadline 前封存，返回可靠引用或预览及存储不可用状态。
// Programmatic 返回带完整性状态的临时缓冲，待交付/放弃后清理，不发布可靠引用。
// 不继承已取消的执行 token；结果中不含工具执行成败，在途 IO 由存储层收尾。
async fn finish(self, end: CaptureEnd, deadline: Instant) -> OutputData;

// 将已物化的文本或结构化结果编码交给存储；可直接消费 String，避免全文复制。
async fn retain(&self, owner: SessionKey, output: OutputData,
                deadline: Instant) -> OutputData;

// 供已有 task_output 等运行时调用方读取指定范围；不暴露成新的 LLM 工具。
// 返回值受预算约束，读取不改变已读状态，缺失/损坏返回明确错误。
async fn read_range(&self, source: &OutputRef, channel: Channel,
                    offset: u64, budget: ByteBudget) -> Result<OutputPage, OutputAccessError>;

// 为完整原文及必要转换缓冲取得内存预留；不足时等待可释放额度。
// 无法容纳的单份数据或不完整采集明确报错，不返回伪装成原文的预览。
// 返回句柄持有预算，直到原生缓冲实际释放；并非按每次结果设置固定大小上限。
async fn materialize(&self, output: &OutputData, memory: &BufferBudget)
    -> Result<HostResultBuffer, MaterializeError>;
```

- **工具协议**：`ToolObject::execute` 改为返回 `Result<OutputData, ToolFailure>`；`ToolFailure` 保留现有 `ToolError` 分类和可选的已采集输出。`Tool::Output` 改为可转成 `OutputData`，String 与现有 Display 输出显式适配，禁止对落盘结果调用 `.to_string()` 重新物化全文。`ToolCallContext` 带会话存储句柄和消费方式：直接调用使用模型展示预算，PTC host 调用使用共享的 BufferBudget，不能把外层展示额度传给中间调用。
- **PTC 内存句柄**：执行开始时拆分日志预留和非日志 BufferBudget；host 调用的上下文及 materialize 只能取得后者，日志采集器持有前者。同步日志入队只等待独立 IO 排空后归还的日志槽位，不申请非日志额度，也不持有 JS 交付路径需要的锁等待 IO。
- **模型可见回查信息**：只为已通过封存屏障的对象附绝对路径、保存字节数、是否完整和预计到期时间，例如 `stdout_file: /.../objects/<id>/stdout.txt`；存储不可用时显示原因，不给出看似可用的残留路径。PTC 只发布最终报告/日志的引用。封存后路径不随会话 fork 改变。内部 OutputId 仅供存储和 task manifest 使用，不要求 LLM 解析 ID 或调用新工具。
- **信任边界：现有文件工具**：LLM 可直接用 `read_file(file_path=...)` 读取或 `grep(pattern=..., path=...)` 搜索，也可使用已授权 shell 命令。沿用原有参数校验和审批；不增加路径自动放行或把路径视为新的授权凭证。查询结果按调用方分别进入模型展示或 PTC 原始数据通路，不因查询落盘文件而放宽相应预算。
- **用户与后台 RPC**：用户可复制路径在服务端查看，或让 agent 使用现有工具查询；不把服务端路径当作浏览器可下载 URL。现有 `get_task_result` 增加有界分页参数，仍校验 session/task 归属，面板读取不确认通知；不接受任意磁盘路径作为 RPC 输入。
- **`read_file`**：保留绝对路径、行 `offset` / `limit`，仍返回带行号前缀的纯文本；页面没读完时末尾给出下一次的行 `offset`。不做字节续读和文件版本校验，两页之间文件被修改时按普通可变文件处理。仍只接受普通文件，保留防 symlink/FIFO 检查。
- **信任边界：普通工具/MCP 返回值**：统一接收 OutputData 或已物化 String，按消费者选择后续通路；格式化错误正文也遵守该边界。PTC 预算覆盖已接管的缓冲和后续复制，不能追溯阻止第三方工具已经完成的大 String 分配，不假设 MCP 传输本身已流式有界。

## Data Model

- `OutputData`：`Inline(text)`、`Buffered(BufferedOutput)`、`Captured(CapturedOutput)`、`Page(page)`。Buffered 是供程序消费的临时内存/文件句柄，带完整性及资源预留，不是历史引用；Captured 带有界预览、采集计数和 `storage = Retained(OutputRef) | Unavailable(StorageFailure)`，允许没有文件引用的正常返回；小结果完整内联时用 Inline。正文可能包含 stdout/stderr 或 PTC value/log，原始工具字符串语义不变。
- `OutputRef`：随机 OutputId、各通道稳定绝对路径、采集字节数、保存字节数、`complete`、丢失原因和封存/到期时间。ID 不编码用户路径、工作区或会话；manifest 记录创建它的工作区和会话，供配额计费。它是文件引用，不是访问控制凭证。
- `ToolMessage.output` 保存最终有界展示字符串；新增 `output_refs` 及 `read_receipts`。output_refs 只含该对外结果通过封存屏障的引用；存储失败类别编码在有界响应的 `storage_failure` 及引用的 `failure` 中，不以残留文件名充当成功引用。引用不混入 FileDiff artifact 或成功工具状态，可随失败/取消结果保存；不得以工具失败为理由丢弃已保留输出。读取凭证列表支持一个 PTC 脚本完成多次读取，但不携带其原始内容。
- 新增 `task_output_progress` 表，以 `(workspace_id, session_id, consumer_pid, task_id, channel)` 为键，保存连续已交付位置；只外键关联 session，避免 rewind 删除消息/进程时撤销交付事实。与消息及现有 `task_notice_receipts` 同事务更新；fork 不复制此表，会话删除级联删除。输出正文及输出对象元数据仍不建数据库表。
- `<output-root>/objects/<output-id>/` 存小型 manifest 及普通通道文件（如 `stdout.txt`、`stderr.txt`、`result.txt`（纯文本）、`result.json`（`run_javascript` 报告）），不使用 ring 布局或要求专用解码。待保留结果运行中为 `Writing`，完成封存后为 `Sealed`，失效为 `Expired`；manifest 标记的 Programmatic 临时对象不进入可靠封存状态，使用结束或重启恢复时清理，同样占用字节及对象数量配额。`complete` 与执行状态正交。无缺失的取消结果表示“采集到取消为止完整”，不表示命令执行完成。文件仅创建/追加，由服务封存后不再修改；本机同用户下的 shell 修改文件不属于存储的隔离保证。
- 面向模型的小输出在内存内联；需要缩成预览时，在预览发布前尝试保存被省略的全文，成功才发布文件引用，失败则按 storage=Unavailable 提交预览。大输出超过采集缓存阈值时提前落盘；因此内存阈值与展示阈值不同也不会漏存。Programmatic 临时缓冲不因超过模型展示阈值而转为保留结果。
- `OutputStore` 是进程级共享实例；统一配额锁管理正在写入的预留量、已保存量及清理量。每会话/每结果计数同一次预留更新，失败回滚；持有全局锁时不等待文件 IO，不同时持有多个结果锁。
- 每会话配额按“由该会话生成的对象”计费，服务总配额按实际对象计费；fork 继承路径不产生额外字节，不重复收费。原会话删除后，残留对象继续计入其原始计费桶及服务总量，直到实际清理；配额索引不能随会话删除而归零。
- PTC 不收集中间结果引用，不生成 `diagnostics.jsonl` 或诊断索引字段；最终报告/显式日志组成一份最多 4 个通道的对外结果。中间临时句柄在交付或放弃后清理，在途 IO 未结束前继续计费；脚本抛错或取消不把中间数据转为历史归档。脚本主动写出的普通文件，以及后台任务已有的保留文件，继续按各自规则管理。

## Load-Bearing Decisions

### 1. 有界采集、顺序落盘与超限行为

- 每个命令 stdout/stderr 合用一个采集对象，初始缓存总量最多 `capture_memory_bytes`；转盘时连同已有缓存写入。落盘后只保留有界首尾窗口，两个通道分别保证预览位置，不把 stderr 饿死。读写块大小固定，临时块及队列也计入有界内存，不以队列保存无限待写数据。
- 写盘按块预留会话和服务配额，单份结果按通道合计。配额包含 payload、manifest 和固定文件分配余量；这是服务管理文件的计费上限，不是文件系统元数据或外部进程写盘的物理保证。
- 空间不足时先回收已过期及最早封存的结果，跳过正在写入或被本次操作短期持有的对象。仍不足或达到单份上限后，保留已有前缀，永久停止该对象后续全文写入，继续统计丢失量及更新有限首尾预览；本次运行不在有缺口的文件后恢复追加。
- 磁盘错误处理同上，不撤销命令副作用，不自动重试执行命令。失效提示区分单份上限、会话/服务配额、对象数量上限、IO 失败及整理超时；命令取消单独记录，不作为存储失败原因。采集丢失不能掩盖原来的退出码和 ToolError。
- 文件 IO 使用有界工作队列，受固定 IO 截止时间约束。执行取消立即停止 producer 并进入有界管道排空和输出整理，已接收的数据及排队写入不能仅因执行 token 取消而丢弃；实际 IO 或整理超时后继续按故障路径处理，尚未完成的系统调用保留其配额预留与句柄，不能提前释放额度或无限提交后续写入。后台故障工作完成后统一结算。
- shell 成功时也能回查 stderr；预览分区展示两路输出。超时保留已采集内容，继续沿用超时错误，不再丢弃所有诊断文本。

### 2. 预算在调用前分配，展示在持久化前完成

- 对一条 assistant message 的 N 个 tool calls（包括待审批和子 agent 调用），按调用顺序分配 `min(single_bytes, floor(batch_bytes / N))`，余数顺序分配；不按完成顺序抢预算，不把审批恢复当成新一批。
- 每份响应预留状态/路径空间，下限为 `max(512 bytes, 当前 output root 下最长合法回查提示的编码大小)`，包含一份结果最多 4 个通道的路径及必要元数据，不能截断绝对路径。PTC 只需容纳最终报告/日志的路径，不随 host 调用数量增长。加载配置时验证 `single_bytes` 足以容纳它；若该批连最小响应都装不下，在保存可执行 tool_calls 和派发副作用之前按无效模型响应结束该次生成，记录有界错误；不得执行一部分后才发现装不下。调用 ID / 名称的协议字段沿用协议验证，不计入正文预算；工具生成的所有正文元数据计入。
- 上述最小响应额度使用配置章节的共享计算，不能在派发时另写一个固定 512 字节下限。首尾预览只在渲染时将截断边缘调整到 UTF-8 字符边界，省略字节数包含因此不展示的字节；不修改原始采集数据，原数据内部的非法 UTF-8 继续按有损解码处理。
- 分配结果写进待执行 checkpoint；恢复使用同一分配，服务端存储上限仍使用重启后的配置。非正常回复、拒绝、未知工具和取消也占原有槽位。已执行的调用不因展示超限变为执行失败。
- 统一完成入口只处理直接返回模型的工具结果及 PTC 最终回复，负责保存全文、选择首尾预览和生成有界 ToolMessage；先为状态、完整性、文件路径及续读信息留空间，按 UTF-8 边界裁剪。状态文本过长也按同一规则尝试归档；归档失败保留有限错误及存储失败说明，不让异常绕过预算。PTC 内部结果不经过此入口。
- 直接返回模型的 `Page` 已由 read_file 或 task_output 按展示预算构建，完成入口只验证而不再裁剪，不能截断后仍提交原来较大的读取游标。不满足预算属于内部错误：不提交该读取凭证，记录有界错误及诊断；PTC 内部页面按第 4 节的程序消费规则处理。
- 历史重开、模型切换或配置降低后，构造 provider 请求时按当前预算再次生成工具消息视图，按原 assistant message 分组；优先利用 output_refs，老消息没有引用时由存储接收其现有正文后生成预览，以会话内 message_id 为稳定来源键去重，不为每次请求重复存档。不会每次读取全文，也不会修改已持久化的执行状态/已读事实。原协议项的配对不能因裁剪破坏；无法容纳最低元数据时停止请求并明确报错。
- 同批限制不是全历史窗口规划；用户输入、工具定义、累计多轮内容仍交给现有上下文管理。

### 3. 分页读取与后台已读确认

- `read_file` 使用固定块扫描定位行号，默认最多返回 200 行，不预先读取全文件或统计总行数。直接返回模型时按本次展示预算分页；PTC 内部调用按文件参数和可预留的程序消费内存分页，不套用模型额度。单行最多展示 2000 字节，超出部分在字符边界截断并标出省略字节数，剩余内容通过 `grep` / `shell` 查看；翻页只按行 `offset`。定位过程定期检查取消；大于 10 MiB 的普通文件也允许范围读取，写入工具原限制不变。
- 原文件作为继续读取来源，不额外复制；输出说明这是可变文件。当前实际返回的分段已经内联受限，不把“原文件全部内容”称为本次调用的已采集全文。
- 后台 shell 改为从启动起使用同一 append-only 存储，避免进程退出前仅在内存保留日志；task manifest 指向 OutputId，不再通过环形覆盖换取常驻空间。超过配额仍按用户选择继续命令。
- `task_output` 保持 shell 增量读取和子 agent 可重复读取，但子 agent 大答案改为有界分页并明确返回续读位置。先给出受预算限制的页面及 `ReadReceipt`，暂不推进已交付游标；实际结果进入 checkpoint 后才提交它。进度改为按 consumer process 独立，避免一个子 agent 的读取替 root 消耗输出；同一 process 的并发重复页只幂等推进一次。
- `ReadReceipt` 包含 consumer、task、通道、起止字节、终态及完整性，仅由 task_output 的受控读取产生。所有通道在终态完整且连续读至末尾才触发现有 root/owner 确认规则；终态零字节响应可确认此前已连续读完的结果，终态到达前的读取本身不确认。通过 read_file/grep/shell 直接查看路径不推进任务游标、不确认通知，不尝试推断任意 shell 命令到底读取了哪些内容；接受这种回查之后仍可能收到一次完成通知。
- 数据库 checkpoint 原子保存输出消息、更新 `task_output_progress` 并写入符合条件的 task notice receipt；commit 成功后才更新内存进度并向归档确认通知。提交响应丢失时沿用 checkpoint 故障停机及权威恢复，不前推游标或重跑副作用。归档只保存内容范围，不再另存权威消费游标，因此无需维护 DB/文件两份进度的一致性。读取进度沿用 notice receipts 的 rewind 不撤销、fork 不复制原则。
- 面板读取、运行中/不完整结果、其他子 agent 读取均不误触发 root 完整结果确认。PTC 的凭证只在结果成功交给脚本且外层按现有语义提交时生效；同一脚本内连续分页使用 staged 进度，成功子调用先合入脚本，外层 checkpoint 再持久化，失败的交付不消费页面。展示摘要不撤销已经交给脚本的真实读取事实。
- 已读不立即删除文件；通知是否已送达与全文是否仍可回查解耦，保留和淘汰由 output store 决定。

### 4. PTC 的原始数据与模型输出分开

- host bridge 将工具的完整原始返回值交给 JS，不替换成预览、不附加中间结果路径、不自动归档。删除原 `result_bytes` 和 `total_result_bytes` 检查；例如脚本逐次处理并释放 100 份 1 MiB 结果，只要时间、调用次数及实际内存允许，就可以完成。
- JS 对象由 `heap_bytes` 约束；Rust 侧采集缓存、在途结果、物化字符串和转换时仍存活的副本由每次执行的 `host_buffer_bytes` 约束。先扣留日志专用空间，其他缓冲只从剩余额度分配，不能借用空闲日志额度。自有生产者在分配前预留，已有缓冲连同预留一起移交，避免重复申请同一份内存；原生缓冲实际释放后归还额度，交给 JS 后由 heap 继续管理。不能在 Promise 入队时提前释放仍存活的原生缓冲，也不要求等待 JS 对象回收才归还已释放的原生内存。第三方工具进入桥接前的分配仍属于明确的范围限制。
- 非日志缓冲暂时没有可用内存时背压，等待已在交付/释放的缓冲归还额度，等待仍受 PTC 总超时和取消约束。启动自有 producer 前预留有界采集空间；未知长度的命令输出超过采集缓存后使用临时文件，完成后按已知完整编码大小一次性申请物化及转换所需额度，不让多个半成品各占一部分内存后互相等待。等待结果交付不能阻止运行中命令的管道排空；采集空间和 IO 队列仍须预留并有界。同步日志不走这条等待结果内存的路径。
- 底层命令的临时采集复用 coda_output，磁盘配额/IO 故障时继续命令并排空；结果不完整时以 `OUTPUT_INCOMPLETE` 拒绝向 JS 交付伪原文。临时文件不需要发布历史引用的持久化屏障，读取前等待相关写入完成，使用完毕即清理；已存在的 read_file 来源及后台任务文件不重复复制归档。
- 单份原文及必要转换缓冲超过扣除日志预留后的全部非日志预算，或 JS 无法分配对应值时，以明确的结果交付错误返回，区分资源不足与采集不完整，并携带原 host 调用的执行状态。暂时性并发占用先等待，不能当作单份数据过大；对不可容纳的数据也不无限等待。错误不把“工具已执行成功”改成“工具未执行”，不隐式重跑有副作用的调用；原有 child staged state/artifact 仍仅在成功交付后合入外层，交付失败不提交，但不能据此宣称外部副作用已回滚。
- read_file / task_output 保留文档化的范围及分页语义，用 PTC 可预留的内存构建完整页面，不能套用外层模型的 16 KiB 等展示限额，也不按累计处理量缩小后续页面。并发读取先预留页面所需缓冲；读取凭证仅在页面实际交给 JS 后合入脚本，再按已有外层提交规则持久化。普通非分页返回值无法完整物化时明确失败，不能悄悄改成分页或截断 JSON。
- `final_bytes` 保留为 JS 最终报告的资源限制：超限返回明确的 `OUTPUT_LIMIT`，不承诺保留无法在该限制内完成的 JS 值。已正常生成且小于这个上限的报告，若超过模型展示预算，则自动落盘，并返回纯文本：首行 `ok: true|false`，接着是报告的首尾预览，末尾逐行给出截断原因和已保存文件路径。
- `console.log` 保持同步语义，是脚本显式提供的对外输出，复用有界采集器及落盘能力。JS 格式化受 heap 限制；原生入口按至多 16 KiB 的 UTF-8 块接收，不能先把完整日志行转换成一个 Rust String 再分块。日志预留中的 `capture_memory_bytes` 用于采集及首尾预览，另 64 KiB 覆盖转换块以及排队/在途 IO 块，移动块所有权而不额外复制；日志再长也不向结果预算借空间。
- 日志排空任务在 JS worker 之外运行，写入、归还队列槽位及故障唤醒均不依赖 JS Promise 调度、结果消费或非日志内存额度；也不能排在等待这些条件的 host 任务后面。队列满时同步调用只等待这条独立排空路径，并受 IO 截止时间、执行超时及取消信号约束，不能依赖 JS interrupt handler 才唤醒原生等待。磁盘正常且写入在期限内时，即使非日志额度全部被待交付结果占用，日志仍可排空、同步调用返回，随后 JS 继续消费结果。
- 日志队列满本身只触发上述背压，不直接丢弃内容；实际配额/IO 故障时停止全文保存、用预留空间维护首尾预览及不完整状态，并唤醒等待方，不再等待结果释放额度。取消时唤醒同步等待，已接收/排队数据沿用第 5 节独立的有界整理规则；在途 IO 未结束前仍持有对应内存及磁盘预留。日志与 value/错误共用最终展示预算，最终序列化使用非日志预算；脚本抛错、超时或取消时保护已采集的显式日志，不补存全部中间返回值。
- 执行超时、heap、原生缓冲、调用数量、并发和最终序列化预算来自本次会话配置；运行时工具描述由实际生效值生成，不能继续展示 `PtcLimits::default()`。

### 5. 稳定文件路径、持久化与清理

- 只有通过通道文件 fsync、manifest 原子替换及目录 fsync 的对象才可返回 Retained(OutputRef)，包括完整保存和已明确标记不完整的前缀文件。后台运行中按已写范围读取使用 live handle，不把未封存路径作为可靠全文引用发布；停止后的封存结果再决定是否有可持久化引用。
- `finish`、展示层 retain 和 PTC 最终报告/日志收尾都必须有出口：生产者停止、按现有管道排空期限完成有界排空后，进入固定 1 秒的输出整理期限。finish、已有缓存/队列写入、fsync 及 manifest 封存共用绝对 deadline，不按文件或重试重新计时；同一取消范围的封存可并行进行。实际存储故障按前述部分保存/失败规则处理，剩余时间耗尽才按整理超时降级。
- 用户取消或执行超时时先立即发出进程组终止和 JS/host 调用取消，停止派发新工作；输出收尾使用独立于已取消执行 token 的 deadline，允许在正常磁盘及配额条件下完成对外结果已采集数据的写入与封存，包括 PTC 显式日志。执行层保留并等待这些有界收尾结果，再按原取消/超时状态提交包含预览和可靠引用的 checkpoint，不能被已触发的 cancel 分支直接丢弃；不恢复被取消执行的 state/artifact 提交资格。PTC 中间临时文件进入清理，不转成历史引用。已经开始整理的调用沿用原 deadline，首次或重复取消均不刷新它。
- 执行终止不等待落盘，工具结果可以在有界排空和最多 1 秒输出整理后返回；这个尾部等待不让命令继续执行，也不取代数据库 checkpoint 的错误处理。已完成部分的存储完整性与 Cancelled/TimedOut 正交；只有配额限制、实际 IO 故障或整理超时才导致相应存储降级。服务进程崩溃或强制退出仍按已有冷启动恢复处理。
- 若 fsync、manifest 替换、目录同步任一步失败或超时，finish 返回有界首尾预览及 Unavailable（失败步骤/原因），output_refs 不加入该对象、正文不暴露其残留路径。原工具的成功/失败/取消、退出码、已发生副作用和成功 state/artifact 提交资格保持不变，driver 仍能提交一个没有可靠文件引用的 checkpoint。数据库 checkpoint 本身若失败，仍按原故障流程处理，不能用输出降级掩盖。
- 降级只依赖始终保留的有界内存预览及短错误码；已经无剩余 IO 预算时不再尝试把错误说明落盘。完整内联结果仍可正常提交；仅有预览时明确“完整结果未可靠保存”。后台 task 的执行状态也与输出存储失败分开，不能据此生成完整结果已读确认。
- 一旦选择 Unavailable，此次返回结果便固定：存储层保留 writer、文件句柄、在途 IO 及其全部预留额度的所有权，标记内部 cleanup pending，停止接纳新写入；未来系统调用即使成功也不再补发引用、不改写已提交消息、不把该残留对象当成后台可读的成功封存结果。等待在途操作结束并关闭句柄后再删文件、核销额度，失败继续计费重试；不能通过丢弃 await future 就释放资源。重启扫描将未发布/不确定对象按实际文件继续计费并清理，不将其自动发布为可靠引用；后台终态消息/manifest 已记录的 Unavailable 优先于迟到的文件封存状态。
- 封存成功后 checkpoint 才能持久化对应引用；数据库只保存有限预览、可靠引用及存储失败说明。数据库提交失败时已封存文件暂留并计费，由后续清理处理，不能删除提交结果未知的引用。
- 后台运行中的进度可读但不承诺每字节抗掉电；正常结束完成上述封存屏障。冷启动依据实际文件和 manifest 交叉校验，未封存对象标记 Interrupted / incomplete，不恢复执行。服务启动先锁目录并扫描所有会话，再开放新的结果写入，不能只统计已 attach 会话。
- 文件在生成预览和 checkpoint 之间持短期 lease；执行取消不提前释放仍在收尾或待 checkpoint 的对象，按正常提交结束或失败处理后释放。普通文件工具不加入这套 lease。清理中的文件删除成功后才释放额度，删除失败继续计费并重试；Unix 下已打开的文件句柄仍可完成读取，随后重新打开可能得到文件不存在。若 lease 或未关闭的存储 IO 仍持有文件，仍计费到释放；外部 shell 持有已 unlink 文件的磁盘使用不属于本服务可精确跟踪的范围。
- 输出对象路径在其生命周期内固定。fork 仅复制已有消息和 output_refs，保留其中绝对路径；不复制文件、不重写历史、不延长保留期限，也不增加跨会话引用计数。已失效路径在 fork 后仍失效；task notice/读取凭证不复制。
- rewind 不立即删除输出文件，不撤销已读交付事实。删除会话先停止其 writer，再删除数据库会话及后台执行元数据；输出文件不随会话立即删除，统一等到到期或配额淘汰。因此删除源会话本身不会使 fork 中的路径失效，但这些文件依然可能被随后清理。
- 每 60 秒进行有界批次清理，写入需要额度时也触发清理，包含已删除会话遗留的对象。过期/淘汰后删除文件与 manifest，原预览保留保存时的期限与完整性说明；现有文件工具返回普通文件不存在错误，不新增结果查询、路径修复或自动重跑机制。保留期限是最长存续时间，配额紧张可以提前淘汰；历史记录不固定占用磁盘。
- output root 必须在重启后保持同一路径；若部署者更换目录或移动到另一台机器，旧绝对路径不自动迁移。部署说明明确这一约束，存储恢复不提供任意历史文本路径重写。
- 旧后台 manifest 的任务状态、通知及 scope 清理事实必须保留；新格式不再写 ring。升级时按既有冷启动流程先结束未完成作用域，再将旧 ring 输出标为不可用并回收，不引入长期双存储兼容层；此行为要写入部署说明。

## Risks / Open Questions

- **首要风险是交付确认顺序**：后台游标、PTC staged effects、checkpoint 和文件引用交叉。先验证最小真实链路的失败/重试，不能等全部接线后才测试。
- 文件封存与数据库 checkpoint 没有共同事务；先文件后 DB，未被历史引用的文件也按期限/配额回收，接受有限期残留。fork 不再引入文件复制事务。删除会话不立即清除输出正文是已确认的稳定路径方案的明确代价，需在部署说明中写明。
- 输出封存超时后的降级和迟到 IO 收尾、PTC 内存预留与结果交付失败及最小正文预算，需要作为故障注入场景验证；不能只测成功落盘后读取全文。PTC 必须统计转换中的原生副本，并避免多个部分物化的结果互相等待额度；累计处理量不能再作为驻留内存的替代指标。
- 同步日志的独立排空必须在真实 JS worker/桥接链路验证：内存分区只解决额度竞争，若排空仍依赖 worker 的单线程 runtime 或等待结果消费的任务，循环等待仍然存在。验证应强制形成待交付结果占满非日志额度的状态，不能只依赖随机并发碰撞。
- 配额覆盖服务管理输出，其他磁盘使用仍可导致 ENOSPC。IO 超时释放调用后仍需计费在途写入；不能把 future 取消等同于系统调用已结束。
- 默认 16 KiB/64 KiB 是起始取值，UTF-8 字节不是 tokens；需用实际中文、长单行和高并发调用样本验证体验，不以压力测试为由更改三层边界。
- MCP、大字符串 JSON 序列化及子 agent 自身生成可能在进入统一结果入口前占用内存；本方案保护已接管的采集与展示，不声称整个模型/第三方结果链路内存有界。
- 普通路径回查继承现有本机文件访问能力，不提供会话间文件隔离；若未来执行工具迁移到容器、远程机器或严格 sandbox，需要重新设计挂载/路径可见性，不能默认沿用此方案。

## Deviations from Design

- 接口草图中的内部范围读取实现为 `OutputReader` + `OutputSnapshot`，后台采集增加 `CapturePurpose::Background` 来保证小结果也可重复读取；模型页面直接携带已封存引用，避免再次归档来源文件。
- 存储失败写入有界响应的 `storage_failure` 和 `OutputRef.failure`，不另增重复的 `ToolMessage.storage_issues` 字段；执行状态仍由原工具结果保留。
- 采集器提前 spill，为原始分块、首尾预览及 UTF-8 渲染副本留出空间；PTC 全文物化按原始字节及通道开销的 12 倍预留，最终 JSON 按编码大小的 32 倍加固定报告空间预留，以覆盖解码、String 容量增长和 JSON 树。它们是实际驻留资源的保守预留，不是累计流量限制，也不改变模型展示预算。
- 历史大消息的请求视图使用由会话和消息 ID 派生的稳定对象 ID，保留期间重复生成请求/摘要不会重复归档或续期；正文及其历史 checkpoint 不被改写。
