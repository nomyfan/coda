## Problem

Coda 的前台命令会把输出完整收进内存，普通工具结果缺少统一的模型上下文大小限制。宽泛搜索、大文件读取或大量日志可能造成内存增长，并让下一次模型请求超过上下文窗口；依赖上一次 usage 触发的自动压缩不能兜住突然出现的大结果。
需要限制采集阶段的资源消耗和模型可见结果的大小，同时让 agent 和用户可以回查被预览省略的内容。超大结果自动落盘是本次明确要求，不是可选增强。

## Scenarios

- agent 执行 shell 命令或宽泛搜索，产生大量输出：执行过程保持有界的输出缓冲，模型只收到有限预览、执行状态及后续读取方式。
- agent 从预览中无法定位测试失败原因，需要读取或搜索结果中间部分：在保留期限和配额内，无需重新执行原命令即可回查。
- agent 读取大文件或收到其他工具的大段文本：单次结果受到统一预算约束，不因绕过 shell 而把全文塞进上下文。
- agent 通过 PTC 分批处理工具结果：中间数据保持原始内容，由 PTC 管理实际内存、在途数据、并发和时间；最终回复才进入模型输出预算，不能因累计处理数据量大而中断低内存占用的脚本。
- 用户排查工具执行问题时，可以访问仍被保留的完整结果；结果不完整、过期或不可读取时，获得明确说明。
- 部署者根据模型上下文窗口、服务器内存和磁盘容量调整 PTC 与输出资源预算，无需修改代码；不配置时使用完整默认值。

## Scope

In:
- 内置前台命令的有界输出采集，以及超大结果的自动落盘、有限预览和按需回查。
- 工具文本结果进入模型上下文的统一预算，覆盖普通调用、MCP、子 agent 返回、后台结果读取及 PTC 最终报告；考虑同一批工具结果的合计大小。
- 面向模型的成功、失败和取消结果均保护已采集输出，保留原有执行状态；回查结果也受展示预算约束。PTC 中间数据不自动归档供历史回查；脚本最终值、显式输出的日志及错误才属于其对外结果。
- 结果存储的配额、保留期限、清理和失败反馈；明确重启、fork、rewind、会话删除对结果引用和可读性的影响。
- 将适合部署调整的预算配置化：模型可见的单次及同批输出预算、前台输出缓冲上限、单份结果大小上限、每会话及服务级磁盘总配额、保留期限。
- 将 PTC 的执行超时、JS heap、原生缓冲及在途结果内存预算、工具调用次数及并发数、最终序列化资源预算配置化；移除固定的单次中间结果限额和累计中间结果流量限额，统一模型展示预算仅作用于最终回复。

Out:
- 本次不重做自动上下文压缩，也不承诺解决任意来源导致的上下文溢出。
- 不提供无限或永久日志归档；不要求新增专门的日志浏览器、下载面板或语义摘要服务。
- 不以此重写 MCP 传输或所有第三方工具的内部内存管理；统一结果预算不能被宣称为这些来源的流式采集保护。
- 不在本需求中锁定存储格式、新工具名称或具体模块拆分。
- 首版不增加配置 UI 或热更新；不要求将所有内部常量配置化，PTC 源码大小、stack 上限和取消等待时间先保留为内部限制，状态及 artifact 限制单独评估，不混入输出预算。
- 不为 PTC 中间结果自动生成预览、持久归档或诊断索引，不新增中间结果查询机制。

## Constraints

- 采集缓冲上限、模型可见预算、磁盘配额是独立约束，不能用 1 MiB 的缓冲上限充当模型输出预算。
- 配置放在 `coda-server.toml`，提供完整默认值，修改后重启生效；模型可见预算支持模型级覆盖，内存和磁盘限制由服务端控制，具体字段及层级在设计阶段确定。
- 区分可调整预算与不可突破的安全上限；明确配置单位、合法范围、覆盖优先级、相互约束及超限行为。服务级磁盘配额必须约束多会话合计占用，不能仅依赖每会话限额。
- 具体默认阈值、单批预算、保留期限及配额在设计阶段确定，并明确采用字节还是 token 计量及估算误差。
- “完整回查”以采集到的结果为准，并受明确的配额和保留期限约束；超限、落盘失败或内容丢失时不得声称全文仍可获取。
- 后台 shell 当前使用会覆盖旧内容的环形文件；设计必须说明如何满足回查要求，不能把现有落盘等同于完整保留。
- 保持取消、超时、审批、工具状态提交和后台结果已读确认的语义，不因预览省略内容误报完整读取。
- PTC 中间结果不得套用模型展示上限；底层命令/文件工具仍须有界采集，必要的临时落盘属于资源管理。真实资源不足时明确区分工具是否已执行和结果是否交付，不把截断数据当原文、不隐式重跑有副作用的调用。
- 工具描述及必要的运行时提示应说明预览、回查和保留限制；项目处于活跃开发期，不要求兼容性垫片。

## Success Criteria

- 持续产生超大 stdout/stderr 的前台命令不会让输出缓冲随累计输出无限增长，也不会因达到缓冲上限停止排空管道而卡住。
- 单次及同批超大文本结果进入模型上下文前均受已定义预算约束，元数据、错误文本和预览提示计入预算，不依赖自动压缩事后处理。
- 面向模型的小结果保持直接可用；超大结果在存储可用、未超配额时自动保存全文，并返回有限预览、完整性说明及可操作的读取方式。
- 在保留期限和配额内，能够按需取得预览省略的中间内容，验证与原始已采集结果一致；回查不会再次无界返回全文。
- 配额耗尽、写盘失败、过期、清理及会话生命周期变化均有确定且可验证的行为，失效引用明确报错，磁盘占用受控。
- 直接调用与 PTC 均不因大小处理改变工具执行状态或静默破坏脚本数据格式；后台结果确认与实际完整读取保持一致。
- 在时间和调用次数允许、实际驻留内存受控时，PTC 顺序处理的数据总量可以超过原累计限额；并发导致暂时内存不足时优先背压，无法物化的单份数据明确报告资源不足，最终回复仍严格限额。
- 缺省配置可正常运行；配置覆盖在重启后作用于对应执行与输出路径，非法或冲突配置在启动时明确报错；多会话并发下服务级磁盘总配额仍有效。
